# Story audit feedback for Claude

วันที่ส่งต่อ: 2026-11-13 (Asia/Bangkok)
ฐานที่ตรวจ: main `65e5621` — ตรวจ concept ที่อนุมัติ, แผนเฟส 3–4, สายเรื่องและ core ที่เรียกใช้

## สถานะและขอบเขต

**ยังไม่ได้แก้เนื้อเรื่องหรือระบบเกม** ผู้ใช้ให้ตรวจและเสนอฉบับขัดเกลาก่อน แล้วขอให้บันทึก feedback เพื่อให้ Claude อ่าน การส่งต่อเอกสารนี้ไม่ใช่การอนุมัติฉบับร่างหรือการเปลี่ยน balance ทั้งหมด

ใช้ `docs/superpowers/specs/2026-11-11-rift-ledger-redesign-design.md` เป็นฐาน: life sim ภาษาไทย ทั้งคนธรรมดาและฮันเตอร์ต้องมีคุณค่า ไม่มีพล็อตผู้กอบกู้โลกบังคับทุกชีวิต หอคอยเป็นซากจักรวาลที่ถูกกลืน

## ข้อค้นพบเรียงตามผลกระทบ

### 1. support:3 → support:4: เพื่อนตายในบท แต่บทต่อไปบอกว่ากลับครบ

ไฟล์ `src/data/stories/hunters.js`, `src/core/stories.js`, `src/core/events.js`

- support:3 เลือก “ยอมรับว่าช่วยไม่ได้” ได้ผล “คุณจับมือเขาไว้จนวินาทีสุดท้าย” แต่ outcome มีเพียง `mind: -20` ไม่แก้สมาชิกทีม
- support:4 เปิดว่า “คนทั้งวงการรู้ว่าทีมไหนมีคุณอยู่ ทีมนั้นกลับมาครบ” โดยไม่ตรวจผลก่อนหน้า
- ตรวจด้วยสถานะควบคุมผ่าน openEvent/choose: สมาชิกทีมยัง `alive: true` หลังเลือกทางดังกล่าว
- ประเภท: ความต่อเนื่องและการเชื่อมระบบ ต้องกำหนดว่าเป็นเพื่อนร่วมทีมจริงหรือ NPC ประกอบฉาก และให้บทถัดไปเคารพผลก่อนหน้า อย่าสุ่มฆ่าสมาชิกทีมเพื่อให้ตรงข้อความโดยไม่มีการออกแบบ

### 2. shop:1 → shop:3: ปฏิเสธสินค้าผิดกฎหมาย แต่ถูกบังคับให้ซ่อนของหรือจ่ายสินบน

ไฟล์ `src/data/stories/careers.js`, `src/core/events.js`

- shop:1 เลือก “ปฏิเสธทั้งหมด” ไม่ได้ `shopLegal` หรือ `shopGrey`
- shop:3 ทางเปิดสต็อกต้องมี `shopLegal: 1` จึงถูกซ่อน เหลือซ่อนของไม่มีใบรับรอง หรือจ่ายใต้โต๊ะถ้ามีเงิน
- ตรวจผ่าน core ด้วยเงิน 10,000: มีเพียงสองทางดังกล่าวที่แสดงและเลือกได้
- ประเภท: เงื่อนไขข้อมูล ต้องรองรับร้านที่ไม่เคยซื้อหินมานา ให้ตรวจทั้งเส้นทางไม่ซื้อ ซื้อถูกกฎหมาย และซื้อของไม่มีใบรับรอง

### 3. office:1 → office:4: สร้างความสัมพันธ์ย้อนหลังที่ผู้เล่นไม่ได้เลือก

ไฟล์ `src/data/stories/careers.js`

- office:1 เลือกปฏิเสธเคลมได้ โดยไม่ได้ `hunterFriend`
- office:4 ทางเปิดบริษัทตรวจเพียง `gold: 15000` แต่ผลบอก “ลูกค้ารายแรกคือฮันเตอร์ที่คุณเคยช่วย”
- ตรวจผ่าน core: `hunterFriend` เป็น 0 แต่ยังได้ข้อความนี้
- ประเภท: ความต่อเนื่อง/เงื่อนไข ให้มีข้อความตามประวัติจริง หรือใช้ข้อความกลางที่ไม่อ้างความสัมพันธ์เท็จ โดยไม่ตัดสิทธิ์เปิดบริษัทของผู้เล่นที่ไม่ได้ช่วยเขาโดยไม่จำเป็น

### 4. sq:seven:0 → sq:seven:1: เจ็ดปีในเรื่องเท่ากับ 12–24 เดือนในระบบ

### 5. office:2: บอกว่าเงินเดือนขึ้น แต่ให้โบนัสครั้งเดียว

## ตัวอย่างน้ำเสียงที่เสนอ: phoenix (ยังไม่ได้รับอนุมัติ)

คง 3 ฉาก จำนวนตัวเลือกเดิม อายุเริ่ม 22–60 ปี hunter=true, gap 8–16 เดือน ตัวนับ `sq:phoenix` และ `give:phoenixToken` เดิม ไม่เพิ่ม stat check หรือรางวัล

### sq:phoenix:0

เดิม: ฮันเตอร์แก่ในโรงพยาบาลฝากจี้ไปให้น้องสาวอีกเมือง รับปากแล้วเขาหลับตายิ้ม ปฏิเสธแล้วเขามองเพดาน

ร่าง:
> ฮันเตอร์สูงวัยบนเตียงริมหน้าต่างเรียกคุณไว้ เขามีซองเล็กๆ จ่าหน้าถึงน้องสาวที่อีกเมือง
> “ข้างในเป็นจี้ของแม่ ฝากส่งให้หน่อยได้ไหม ฉันรับปากว่าจะเอาไปคืนเขา”

- “รับปากว่าจะส่งให้” → “คุณเก็บซองไว้ เขาถามย้ำว่าลายมือบนซองยังอ่านออกไหม ก่อนยอมปล่อยมือ” เพิ่มตัวนับเดิม
- “บอกว่าคงช่วยไม่ได้” → “เขาพยักหน้าแล้วเก็บซองกลับไว้ใต้หมอน ‘ไม่เป็นไร ขอบใจที่ฟังนะ’” ไม่เดินเรื่องต่อ

### sq:phoenix:1

เดิม: พบน้องสาวในชุดไว้ทุกข์ ส่งจี้และเล่าเรื่องแล้วเธอร้องไห้และขอให้กลับมา หรือวางจี้ไว้แล้วไป

ร่าง:
> คุณมาถึงบ้านตามที่อยู่บนซอง หญิงที่เปิดประตูยังติดริบบิ้นไว้ทุกข์ พอเห็นชื่อผู้ส่ง เธอก็จับขอบประตูแน่น
> “คุณเจอพี่ครั้งสุดท้ายเมื่อไหร่”

- “ส่งจี้ให้ แล้วเล่าถึงวันที่พบเขา” → “เธอฟังจนจบ ก่อนวางจี้ไว้ข้างรูปพี่ชาย ‘ขอบคุณที่ยังจำเรื่องที่รับปากไว้’ ก่อนคุณกลับ เธอขอที่อยู่ติดต่อ” เพิ่มตัวนับเดิม
- “วางซองไว้หน้าประตูแล้วจากไป” → “คุณวางซองไว้โดยไม่ได้คุยกัน และไม่รู้ว่าเธอเปิดอ่านเมื่อไหร่” ไม่เดินเรื่องต่อ

### sq:phoenix:2

เดิม: น้องสาวส่งกล่องที่มีเหรียญอุ่น พร้อมข้อความว่ามันเคยพาพี่กลับมาครั้งหนึ่ง รับไว้แล้วได้ Phoenix Token

ร่าง:
> พัสดุจากน้องสาวของเขามาถึง ข้างในมีเหรียญที่อุ่นทั้งที่กล่องเย็น พร้อมจดหมายสั้นๆ
> “พี่เก็บไว้เผื่อวันที่กลับออกจากเกตไม่ได้ แต่ไม่ทันได้ใช้ ฉันอยากให้มันอยู่กับคนที่ยังต้องเข้าไป”

- “เก็บเหรียญไว้” → “คุณเก็บจดหมายแยกไว้ ส่วนเหรียญอยู่ในกระเป๋า ความอุ่นของมันไม่จางลงเลย” เพิ่มตัวนับและให้ไอเทมผ่าน action เดิม

เหตุผล: เติมที่อยู่สำหรับส่งจี้ ช่องทางส่งพัสดุกลับ และแรงจูงใจที่ญาติยอมให้ของสำคัญ แสดงอารมณ์ผ่านการกระทำมากขึ้น โดยไม่ประกาศความสามารถของรางวัลตรงๆ

## แนวทางส่งต่อ

1. ให้เจ้าของตรวจน้ำเสียง phoenix ก่อนลงร่างนี้ในเกม
2. แยกงานภาษาออกจากงานแก้เงื่อนไขของ shop/office/support และเวลา seven
3. ก่อนแก้จริงตรวจ main ล่าสุดอีกครั้ง ข้อค้นพบนี้อาจถูกแก้ไปแล้วในภายหลัง
4. รักษา IDs, counters, placeholders และไม่เปลี่ยน balance โดยแอบรวมมากับการขัดเกลาบท
5. เมื่อได้รับอนุมัติให้แก้ ใช้ branch claude/story-<หัวข้อ> รัน regression ที่จำลองเส้นทางข้างต้น, npm test และ simulation ที่เกี่ยวข้อง เปิด PR เข้า main ห้าม push ตรงหรือ merge เอง

## ขอบเขตหลักฐาน

ข้อ 1–5 ตรวจข้อมูลและใช้สถานะควบคุมเรียก core จริงใน snapshot ของ main ไม่ใช่ playthrough ทุกชีวิต ข้อ 6 เป็นข้อเสนอเชิงบรรณาธิการ รอบตรวจนี้ไม่ได้แก้ source และไม่ได้รัน simulation ทั้งเกมเพื่ออ้างความพร้อมหลังแก้
