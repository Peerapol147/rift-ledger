# บรีฟต่อให้ Claude — 13 พฤศจิกายน 2026

เจ้าของขอให้ฝังบรีฟในโปรเจกต์เพื่อทำงานต่อได้จริง อ่านไฟล์นี้พร้อม `HANDOFF.md`,
`../CLAUDE.md`, `../AGENTS.md` และ [roadmap](superpowers/plans/2026-11-13-improvement-roadmap.md).
ใช้ Superpowers และสกิลโปรเจกต์ที่ตรงกับงาน อ่านคำสั่งจริงก่อนใช้ ไม่อ้างว่าใช้สกิลที่ไม่มีอยู่.

## เป้าหมายที่เจ้าของย้ำ

- เล่นและกดง่ายทั้งมือถือและคอม โดยผู้เล่นเป็นคนตัดสินใจเองเป็นค่าเริ่มต้น
- เนื้อเรื่องสำคัญเท่าระบบ: การเลือกต้องมีเหตุผล มีผลต่อเนื่อง และเรื่องคนธรรมดาต้องมีน้ำหนัก
- ใช้เกมคู่เทียบเพื่อเรียนรู้หลักการ ไม่คัดลอกโค้ด ภาพ บท ตัวละคร หรือสูตร
- กรอบตัวละคร แรงค์ และอาชีพต้องมีเอกลักษณ์; รูปร่างต้องสัมพันธ์กับอายุ
- ทำงานที่อนุมัติแล้วต่อได้โดยไม่ถามซ้ำ แต่ไม่ถือว่าอนุญาตให้ merge main หรือเผยแพร่ระบบใหม่โดยอัตโนมัติ

## เพิ่มเติมจากเจ้าของ: ท่าขยับและเพลง

เจ้าของแก้ทิศทางล่าสุด: ทารกต้องไม่ใช้ผมทรงเด็กโต และตัวละครตั้งแต่เด็กถึงแก่รวมทุกคลาสต้องขยับได้.
**คำสั่งล่าสุดแทนแนวทางเดิม:** เจ้าของปฏิเสธ pixel-region displacement, CSS หมุนทั้งภาพ
และทารกวาดจากโค้ด เพราะลายเส้นไม่เข้ากันและขยับไม่ดี. ห้ามคืนวิธีเหล่านี้.
ดู [แผนทำใหม่](superpowers/plans/2026-11-13-animation-rebuild.md) และ `art/animation/README.md`.

- สร้างจาก image_gen โดยอ้างอิงภาพเดิมของโปรเจกต์ ไม่อ้างอิงภาพเกมคู่เทียบ.
- 68 sprite strips: 8 วัย + 15 คลาส + 11 ชุดอาชีพ × หญิง/ชาย, ชุดละ 4 เฟรม รวม 272 เฟรม.
  doctor/hunter doctor ใช้ชุดหมอร่วมกัน จึงรองรับ 12 career IDs.
- `s.sex` เลือกภาพทั้งฉากและโปรไฟล์; เซฟเก่าไม่เปลี่ยน schema.
- `character-identity.js` เลือก identity และ frame; `character-frames.js` decode PNG ตามต้องใช้;
  `character-sheets.gen.js` สร้างจาก manifest. ห้ามแก้ generated map ด้วยมือ.
- ฉากใช้เฟรมเต็ม ไม่ตัดขยับหัว/แขน; กรอบใช้ steps(4) เลื่อนแถบเฟรม ไม่หมุนรูป.
  ฉากพักเฟรมแรกระหว่างต่อสู้/เดินทางและ calm; โปรไฟล์รองรับ OS reduced-motion.
- แต่ละ strip 256×64, 4 cells 64×64, baseline 60, alpha binary, palette จำกัด 48 สี.
  เก็บ source sheets และ prompt ใน `art/animation/generation.json`; pipeline ทำซ้ำได้ด้วย
  `python tools/normalize-character-sheets.py` แล้ว `python tools/check-character-sheets.py`.
- เมื่อเพิ่มคลาส/อาชีพ ต้องเพิ่มทั้งหญิงและชายและทดสอบ coverage ห้ามยืมภาพเพศอื่นเงียบ ๆ.
- ภาพเก่าคงไว้เป็น reference และ fallback ระหว่าง PNG decode เท่านั้น.

เพลงแก้ให้ปุ่มอยู่เหนือหน้าจอเริ่ม กดเปิดครั้งเดียวหลัง autoplay ถูกบล็อกได้,
แสดงสถานะเล่นจริงพร้อมข้อผิดพลาด และไม่ให้คำตอบจากการเล่นครั้งเก่าทับสถานะใหม่.
อย่ากลับไป toggle จากค่า preference เพียงอย่างเดียว. ทดสอบเสียงด้วย currentTime ของ MP3 ที่ฝังใน build;
การทดสอบ headless ไม่ยืนยันระดับเสียงลำโพงจริงของอุปกรณ์เจ้าของ.

หากพัฒนาภาพต่อ ให้เพิ่ม action sheets แยกจาก idle และรักษา palette/ขนาด/จุดยืนจาก manifest;
ไม่เปลี่ยนท่าพักให้กลายเป็นการโจมตีจริงและไม่ทำให้ข้อมูลลับเผยผ่านภาพ.

## ฐานงานที่ต้องรักษา

สาขาส่งมอบ `claude/responsive-ui` มี implementation commit `030aab3` ต่อจาก
`da275a7` (วิจัยและแผน) และ `98e5332` (ค่าเริ่มต้นและเพลง).
ก่อนเริ่ม fetch และตรวจฐานจริง อย่าใช้หมายเลข main ในเอกสารเก่าแทนสถานะล่าสุด.
หากทำบนสาขาอื่นให้ตรวจว่ามีการเปลี่ยนแปลงเทียบเท่าแล้วหรือยัง ก่อนนำเข้าครั้งเดียว.
อย่า reset งานผู้อื่นหรือเขียนทับเซฟเจ้าของเพื่อสร้าง fixture.

สิ่งที่ทำแล้ว:

1. เริ่มที่ 1× / หยุดรอตัวเลือก รวม migration การตั้งค่าเก่า; ผู้เล่นเลือกออโต้เองภายหลังได้
2. ฝัง Shadow's Resolve ใน `play.html` ไม่ต้องดาวน์โหลด MP3 แยก
3. เลือกเหตุการณ์เมื่อแตะสำเร็จ ป้องกันแตะยกเลิก/ลากเลื่อนและเลือกเหตุการณ์คนละอัน
4. หน้าตั้งค่าคุมโฟกัสและปุ่มลัด เก็บข้อความนำเข้า และแสดงผลแจ้งเตือนเหนือหน้าต่าง
5. ของ/การค้นหาอัปเดตโดยไม่เสียโฟกัส เกณฑ์ขายของแสดงตรงกับค่าที่ใช้จริง
6. พักเวลาในหน้าตัวฉัน/ของ/ทีม/งาน/แผนเดือน พร้อมปุ่มกลับไปใช้ชีวิต
7. แผนเดือนเข้าถึงได้บนมือถือ ปุ่มใหญ่ขึ้น ไม่มี 16× ที่ระบบไม่รองรับ
8. กรอบอาชีพและแรงค์จากงานของเรา ไม่ใช้ศักยภาพลับหรือความหายากมาตกแต่งให้เดาได้
9. ต่ำกว่า 12 เดือนใช้ภาพทารกห่อตัว; 12–35 เดือนเป็นวัยเตาะแตะ ภาพพลเรือนในกรอบใช้ตัวเลือกช่วงวัยเดียวกับฉาก

หลักฐานรอบส่งมอบ: 201 core tests และ 10 Chromium interaction scenarios ผ่าน;
artcheck, linelen และ build ผ่าน มี art requests เดิมค้าง 11 รายการ ไม่ใช่ข้อผิดพลาดใหม่.
ดู [รายละเอียดและข้อจำกัด](feedback/ux-refresh-2026-11-13.md).
นี่เป็นผลของ commit ข้างต้น ต้องรันใหม่หลังแก้ ไม่อ้างว่าผ่านทุกอุปกรณ์.

## ลำดับทำต่อและเงื่อนไขจบ

### 1. ทำให้เซฟเชื่อถือได้ — phase A ส่วนที่เหลือ

อ่าน [A](superpowers/plans/2026-11-13-phase-a-trust.md) และ
[รายงานบั๊ก](feedback/ux-2026-11-13/REPORT.md). ปิด A3/A4 ร่วมกัน:
ห้ามแจ้งเซฟสำเร็จเมื่อเขียนไม่สำเร็จ, ตรวจข้อมูลนำเข้าก่อนแทนของเดิม,
จัดการการลบ/กู้คืน/backup และข้อมูลจากเวอร์ชันอนาคตโดยไม่ทำลายต้นฉบับ.
ตรวจ A1/A2 เทียบโค้ดใหม่เพื่อปิดเฉพาะส่วนที่มีหลักฐาน ไม่ติ๊กจบทั้ง phase เพราะ UI ดีขึ้น.

จบเมื่อมี regression ของ storage failure, malformed import, future-version primary + old backup,
การยกเลิกและการกู้คืน และทุกกรณีรักษาข้อมูลเดิมตามสัญญาในแผน.

### 2. เริ่มตรวจเนื้อเรื่องทันที — C0 ไม่ต้องรอเซฟครบ

อ่าน [C](superpowers/plans/2026-11-13-phase-c-narrative.md).
ตรวจ 12 career chains, 5 hunter chains และ 8 team templates จากข้อความและเงื่อนไขจริง.
บันทึกเส้นทางที่ตรวจแล้วและยังไม่ได้ตรวจ; จำนวนบทไม่ใช่หลักฐานว่าเรื่องต่อเนื่อง.
เริ่มจาก N01 ปฏิเสธเงินกู้แต่ภายหลังมีการคืนเงิน และ N02 ข้อความลา/หายไปที่ state ไม่รองรับ.

จบ C0 เมื่อมีตารางเหตุ–ผลของทางเลือก และ story bible ต้นฉบับสำหรับคนธรรมดาและฮันเตอร์.
หลังฐานเซฟพร้อม ทำ C1/C2: แยกเปิดบทออกจากเลือกจบจริง, ผลเกิดครั้งเดียว,
journal อ่านจากผลที่เกิดจริง ไม่เดาอดีตจาก counter และไม่เผยความลับ.

### 3. เติมข้อมูลก่อนตัดสินใจ — B2/B3 และช่องว่าง B1

อ่าน [B](superpowers/plans/2026-11-13-phase-b-decisions.md).
บอกต้นทุน ข้อจำกัด และความพร้อมที่ตัวละครรู้ได้ก่อนกด ใช้ state จริง.
รักษาการพักเวลาและตำแหน่งปุ่มที่ส่งมอบแล้ว ไม่เพิ่มออโต้หรือเปลี่ยนสมดุลโดยแอบแฝง.
จบเมื่อผู้เล่นอ่านเพื่อเตรียมตัวได้บนจอ 320px และข้อมูลไม่เปิดเผย hidden rank/ceiling.

### 4. เขียนและเล่นอ่านเรื่องครบทาง — C3/C4

ทำสอง pilot arcs ต้นฉบับ: คนธรรมดาหนึ่ง ฮันเตอร์หนึ่ง มีความขัดแย้ง ทางเลือก ผลระยะสั้น
และผลย้อนกลับที่สอดคล้องกัน รวมบทปิดและความทรงจำสาธารณะที่ส่งต่อสู่ทายาท.
เรื่องต้องไม่กลายเป็นแค่เพิ่มค่าสถานะ; การปฏิเสธหรือเลือกทางอื่นต้องมีความหมาย.
ทดสอบทั้งทางเลือก จังหวะตาย/เกิดใหม่ และความจำที่ทายาทมีสิทธิ์รู้.

### 5. ตรวจและส่งมอบ — D

อ่าน [D](superpowers/plans/2026-11-13-phase-d-validation.md).
รัน `npm test`, `node tools/artcheck.mjs`, `node tools/linelen.mjs`, `npm run build`.
รัน `node tools/ux-regression.mjs` โดยเสิร์ฟ repo ที่ 5183 หรือกำหนด `UX_URL`;
กำหนด `PLAYWRIGHT_MODULE`/`CHROMIUM_PATH` ให้ตรงเครื่อง.
ทำ simulation ตามส่วน core ที่แก้ และเล่นอ่านทุกเส้นทาง pilot จริง.
ตรวจ default รอผู้เล่น, เพลงหลังผู้เล่นเปิดเสียง, import/export, จอเล็ก/ตัวใหญ่,
คีย์บอร์ดและทัช รวม screenshot หลักฐานของ build ใหม่.

แต่ละชุดให้ commit แยกงาน อัปเดตสถานะและหลักฐานใน HANDOFF แล้ว push สาขางาน.
สร้าง PR เมื่อเข้าถึง API ได้; ณ รอบนี้ push สำเร็จแต่ GitHub API ถูกบล็อก จึงยังไม่มี PR
ที่สร้างโดย Codex และยังไม่ merge main. อย่าอ้างว่าทำครบทั้ง roadmap จนผ่าน release gate.

## สิ่งที่อย่าทำตกหล่น

- ห้ามส่ง build เก่าทับ UX/เพลง/ค่าเริ่มต้นชุดนี้
- ห้ามใส่ HAR ดิบ ข้อมูล session หรือ source คู่เทียบลง Git
- ไม่ลดเรื่องคนธรรมดา/ผลย้อนกลับเพื่อแลกกับหน้าจอสวยอย่างเดียว
- งานภาพใช้ของเดิมก่อนถ้าตรงโจทย์; ถ้าขาดให้เปิด art request ตามสัญญาโปรเจกต์
- บันทึกข้อจำกัดและงานค้างตามจริง ไม่ใช้คำว่าเสร็จทั้งหมดแทนผลตรวจ

## ล่าสุด: มอนสเตอร์และ PixelFX

ติดตั้ง `tools/skills/pixelfx/SKILL.md` จาก ZIP เจ้าของ (MIT แยกจากสกิล Apache).
ใช้คำสั่ง render/check จาก `vendor/pixelfx` ซึ่งมี tools และ docs แล้ว.
Runtime core/effect sources ตรงกับ ZIP จึงไม่เขียนทับ. ใช้ create-game-assets + Superpowers.

มอนสเตอร์ใหม่ตามเนื้อเรื่อง: ปลาไร้น้ำ, เงาใต้ท่าเทียบ, ผู้โดยสารคนสุดท้าย,
อาจารย์ที่ยังสอนอยู่. PNG56×56, 14 สีสูงสุด, transparent; เลิกยืมภาพตัวอื่นทั้ง 4 ตัว.
สังเกต orientation: ภาพใหม่หันซ้ายอยู่แล้ว ส่วนภาพเก่ายังคง flip เดิมใน stage.
`LEFT_FACING` ใน monster-art.js ต้องเพิ่มเมื่อ author ภาพใหม่หันซ้าย.

เอฟเฟกต์: สัตว์มีรอยกรงเล็บสีงาช้าง; วิญญาณกระทบเป็นแสงฟ้าอมเขียวสั้น ๆ;
ชนิดอื่นแรงกระแทกสีหม่น. transient VFX จำกัด 4 ตัวพร้อมกัน / ชื่อเดียวไม่เกิน 2.
ลด glow และตัด impact คริติคอลซ้อน (ยังมี damage text / hit-stop); calm ไม่สร้าง transient VFX.
ไม่เพิ่ม aura ถาวรและไม่เปลี่ยน damage, story, balance. พรีวิวคำสั่งในสกิลก่อนเพิ่มเอฟเฟกต์.
ยังเหลือ art requests 7 ตัว ไม่ถือว่า monster roster ใหม่ทั้งหมดเสร็จ.
