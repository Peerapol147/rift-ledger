## 0. คำสั่งล่าสุดของเจ้าของ (2026-11-14) — สำคัญที่สุด

- **"ใช้บทเหมือนเกมเขาเกินไป ต้องปรับแต่ง"** เกมต้นแบบ Way of Xian เป็นแหล่งอ้างอิง *กลไกและความรู้สึก* เท่านั้น
  ห้ามลอกหน้าตา ถ้อยคำ โครงบท หรือชื่อเรียก งานถัดไปต้องทำเป็นของ Rift Ledger เอง: โลกฮันเตอร์ เกต หอคอย กิลด์
  เมืองไทย/เกาหลีหลังวันฟ้าแตก ไม่ใช่โลกบำเพ็ญเพียร
- สิ่งที่ห้องก่อนทำตามต้นแบบใกล้เกินไป **ให้ทบทวนและปรับเป็นสไตล์เราเอง** (เสนอเจ้าของก่อนแก้ใหญ่):
  1. การ์ดตัวเลือกกลางจอ + ปุ่มพับ + "เปิดเรื่องใหม่แบบพับไว้" + กรอบทึบ/ประตามแผน (`#choice`,
     `docs/superpowers/specs/2026-11-14-choice-card-design.md`) — โครงเดียวกับต้นแบบเกือบทั้งหมด
     ข้อเสนอ: เปลี่ยนเป็น "แฟ้มภารกิจ/ใบแจ้งเหตุ" แบบสมาคมฮันเตอร์ (หัวกระดาษ ตราสมาคม ระดับเหตุ F–S แทนสีความหายาก)
     หรือข้อความวิทยุ/แจ้งเตือนมือถือสำหรับคนธรรมดา; ชื่อปุ่มเป็นภาษาโลกเรา เช่น "เก็บแฟ้มไว้ก่อน"
  2. แถบบน `#who` (ชื่อ · อายุ · แรงก์ · "ช่วงชีวิต") และบรรทัดมุมฉาก `#where` — โครงเดียวกับ topbar/scene-text ของเขา
     ข้อเสนอ: ทำเป็น "บัตรฮันเตอร์/บัตรประชาชน" ขนาดเล็ก (เลขทะเบียนสมาคม แรงก์ประทับ) และมุมฉากเป็นป้ายแบบ
     กล้อง CCTV/ข่าวด่วน (เวลา เมือง เขต) แทนชื่อสถานที่+กิจกรรม
  3. คำ "ช่วงชีวิต" (`src/core/chapter.js chapterOf`) เป็นแนวคิด "บทชีวิต" ของต้นแบบ ปรับคำให้เป็นสถานะในโลกเรา
     เช่น "ขึ้นทะเบียนกิลด์…", "ฮันเตอร์ไร้สังกัด", "พักใบอนุญาต" (ยังอ่านจากสถานะที่เห็นได้เท่านั้น ห้ามเผยความลับ)
- ลำดับ UX เดิมที่ตกลงไว้ (ส่วน 3 การ์ดคน + ช่วงสำคัญตอนตาย, ส่วน 4 ธีม/½×/หน้าโหลด) **ให้ออกแบบใหม่ในสไตล์เรา**
  ก่อนทำ ใช้ brainstorming ถามเจ้าของว่าอยากให้ "เป็นตัวเอง" แบบไหน

## 1. วิธีทำงาน (เหมือนเดิม)

superpowers ทุกครั้ง: brainstorming → เอกสารออกแบบ (+ builder check ด้วย subagent) → writing-plans →
executing-plans (TDD ทุกข้อ ทำให้ล้มก่อน, ledger ใน `.superpowers/sdd/<plan>/progress.md`, Ruling ทุกการเบี่ยง) →
ผู้ตรวจ opus ทั้ง branch → แก้ Critical/Important ด้วยการตรวจที่ล้มก่อน → finishing-a-development-branch
บั๊ก: systematic-debugging ก่อนแก้เสมอ เจ้าของพูด "รวมเลย" = เปิด PR + merge แล้วตั้ง branch ใหม่จาก main
ตอบเจ้าของเป็นไทยง่าย สั้น เจ้าของ token จำกัด: เก็บ output ยาวลงไฟล์ อ่านแค่ท้าย

## 3. งานถัดไป (ลำดับแนะนำ)

1. **ทบทวน UX ให้เป็นของเราเอง** (ข้อ 0) — เสนอเจ้าของก่อน แล้วค่อยแก้ทีละส่วน การตรวจ `C-*` `T-*` ต้องผ่านต่อ
   (เปลี่ยนตัวเลือก selector ได้ถ้าโครงเปลี่ยน ห้ามลดสิ่งที่ตรวจ)
2. เจ้าของจะเล่นแล้วบอก "อาชีพ/เส้นทางที่ยังไม่เวิร์ค" — ทำทีละอาชีพ ใช้ systematic-debugging + จำลองชีวิตจำนวนมากหาแพทเทิร์น
   (แบบที่หาวงจรหนี้) ถ้าเจ้าของส่งเซฟมา: ตั้งค่า → ส่งออก ได้ข้อความเซฟ ใช้ `C.deserialize`
3. P2b-2 cast แต่งงาน/มีลูก (รุ่นลูกคนเกาหลีเจอเรื่อง cast 0%, รุ่นลูกไทยเจอแค่พิมพ์) แล้ว P2b-3 ดาวคู่ตอนเกิด
   (ตกลงแล้ว: บอกเป็นลางตอนเกิด ไม่บอกชื่อคน รู้ตัวตอนเจอในเรื่อง)
4. minor ค้าง: เพดานหนี้ขยับตามรายได้ (หนี้ค้างเหนือเพดานได้), ข้อความยาวบนแถบบน/มุมฉากไม่ตัดบนจอแคบ, มุมฉากมี " · "
   นำหน้าถ้าไม่รู้สถานที่, aria-label การ์ดเป็นแท็กไม่ใช่ชื่อเรื่อง, ทุกรอบต่อสู้เปิดการ์ดใหม่, `C-auto` ตรวจอ่อน,
   แบนเนอร์นำเข้าล้มเหลวไม่ urgent, ข้อความ "อีกแท็บ" ขึ้นกรณีนำเข้าเซฟเก่า, ป้าย "เปลี่ยนชีวิต" บนตัวเลือก (ต้องมี flag ข้อมูลใหม่)
