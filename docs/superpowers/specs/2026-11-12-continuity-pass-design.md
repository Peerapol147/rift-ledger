# รอบปรับความต่อเนื่อง: เทียบกับเกมแนวเดียวกัน แล้วซ่อมฐานก่อน

สถานะ: เจ้าของเกมมอบให้ผู้ออกแบบตัดสินเอง ("ตามสมควร") · วันที่ 2026-11-12

## ทำไม

เจ้าของเกมเล่นแล้วรู้สึกว่า "มั่ว": เหตุการณ์ เนื้อเรื่อง ความต่อเนื่อง ความสนุก layout และการปลุกพลัง เมื่อเทียบกับเกมจำลองชีวิตแนวบำเพ็ญเพียรอีกเกมหนึ่งที่เจ้าของเกมชอบ เป้าคือ "ประสบการณ์ใกล้เคียง" โดยเอา **แนวคิดและกลไก** มาใช้ ไม่ลอกโค้ด ข้อความ ตัวละคร หรือชื่อของเขา

## สิ่งที่วัดได้ (ผู้ออกแบบ เล่นบอท 200 ชีวิต)

| ปัญหา | ตัวเลข |
|---|---|
| เหตุการณ์เดิมมา 3 ครั้งขึ้นไปในชีวิตเดียว | 25 เรื่อง เกิดใน 100–196 จาก 200 ชีวิต (งานเลี้ยงรุ่น 196, ยิม 193, ปวดหลัง 192) |
| ข้อความไม่เว้นวรรค `เกตแรงก์ Bแตก` | เกิน 1,000 บรรทัด |
| ชื่อหอเต็มยาวปนกลางประโยค `ทำลายสถิติThe Silent Tower (หอเงียบ)` | 459+ บรรทัด |
| คู่ชีวิตโผล่มาโดยไม่เคยเจอ (`adultLove`: "คนที่คุณคบมาหลายปี") | ทุกชีวิตที่ได้เหตุการณ์นี้ |
| สมาคมโทรเรียกฮันเตอร์อายุ 87 ไปสู้เกตแตก | `hunterBreakCall` ไม่มีเพดานอายุ |
| เด็ก 1 ขวบมีแผน "ออกกำลัง" "ช่วยงานบ้าน" | แผนของเด็กใช้ชุดเดียวตั้งแต่ 0–12 |
| ตื่นพลังตอนอายุ 18 พอดี | 35 จาก 37 ฮันเตอร์ |
| เหตุการณ์สุ่มทั้งเกมมี 150 เรื่อง ผู้ใหญ่ 18–60 สุ่มได้ราว 110 ครั้ง จากกองราว 85 เรื่อง | การซ้ำจึงหนีไม่พ้นด้วยกติกาเดิม (ซ้ำได้ 4 ครั้ง เว้น 5 ปี) |

## สิ่งที่เกมต้นแบบทำแล้วได้ผล (กลไก ไม่ใช่เนื้อหา)

1. ตัวละครประจำเรื่องที่มีชื่อ กลับมาอีกหลายปีต่อมา และเรื่องอ้างถึงเหตุการณ์เก่า
2. เรื่องเดินเป็นขั้น แต่ละขั้นรอเวลาหรือรอเงื่อนไข เรื่องหนึ่งเล่ายาวหลายปี
3. "บทของชีวิต" เปลี่ยนชนิดเหตุการณ์ที่จะเจอ
4. เส้นชะตาตั้งแต่เกิด วิ่งคู่ชีวิตและมาแน่นอน
5. ตัดสินใจส่วนใหญ่ครั้งเดียวต่อชีวิต ที่ซ้ำได้ต้องประกาศพร้อมระยะพัก
6. จังหวะชีวิตของคนธรรมดาปรับได้ (เร็วขึ้น) ไม่ปล่อยให้ว่าง

## แนวทางที่พิจารณา

- **A. ซ่อมฐานก่อน แล้วเพิ่มความต่อเนื่องทีละชั้น** (เลือก): แก้ที่ต้นเหตุ ใช้แรงมากสุด
- B. เติมเหตุการณ์จำนวนมากอย่างเดียว: ดูเยอะขึ้นเร็ว แต่บั๊กและความไม่สมเหตุสมผลยังอยู่
- C. ยกโครงของเกมต้นแบบมาทั้งหมด: รื้อใหญ่ เสี่ยง และกลายเป็นลอก

## แผนรวม 4 ส่วน (ทำทีละส่วน ส่วนละ PR)

1. **ฐานที่สมเหตุสมผล** (เอกสารนี้ลงรายละเอียด)
2. **ตัวละครประจำ:** เพื่อนสนิท คนรัก คู่แข่ง พี่เลี้ยง มีชื่อ เกิดจากเหตุการณ์ และถูกอ้างถึงในเหตุการณ์ถัดไป (ออกแบบแยก)
3. **การปลุกพลังเป็นกระบวนการ:** ลางตั้งแต่เด็กที่ผูกกับค่าที่ซ่อนอยู่ การตรวจตอน 18 ที่มีบทนำ และการตื่นช้าที่มีเหตุ (ออกแบบแยก)
4. **layout:** หน้าบันทึกอ่านง่าย แยก "เรื่องสำคัญ" กับ "ข่าว" ไม่มีอะไรลอยทับ (ออกแบบแยก ใช้ `tools/skills/game-ui-ux`)

## ส่วนที่ 1: ฐานที่สมเหตุสมผล

**เป้าหมาย**
- ไม่มีเหตุการณ์สุ่มเรื่องไหนมาเกิน 1 ครั้งต่อชีวิต เว้นแต่ข้อมูลประกาศว่าซ้ำได้ (`cap`) และเรื่องที่ซ้ำได้ต้องเว้นอย่างน้อย 5 ปี
- ไม่มีข้อความเพี้ยน: เว้นวรรครอบตัวอักษรแรงก์ ชื่อหอในประโยคใช้ชื่อไทยสั้น (`หอเงียบ`, `หอจมน้ำ`) ส่วนชื่อเต็มอังกฤษใช้ในหัวข้อเท่านั้น
- เหตุการณ์ไม่ขัดกับสภาพชีวิต: คนรักต้องเคยพบกันก่อน ฮันเตอร์สูงวัยหรือเลิกล่าแล้วไม่ถูกเรียกไปสู้ เด็กเล็กมีแผนที่เหมาะกับวัย
- ช่วงที่ไม่มีอะไรให้เลือกไม่ยาวขึ้นจนน่าเบื่อ: มัธยฐานของ "ช่วงว่างนานสุด" ใน playtest ไม่เกิน 2 ปี (เท่าปัจจุบัน)
- มีเครื่องมือตรวจอัตโนมัติ `tools/lifecheck.mjs` ที่เล่นหลายชีวิตแล้ว fail เมื่อพบการซ้ำเกินกติกา ข้อความเพี้ยน หรือเหตุการณ์นอกช่วงอายุ ใส่ไว้ใน `npm test` แบบจำนวนชีวิตน้อยเพื่อให้เร็ว

**ไม่ทำในส่วนนี้:** ระบบตัวละครประจำ การปลุกพลังแบบใหม่ การจัด layout ใหญ่ งานภาพใหม่

**ล้มเหลวแม้ผ่านเทสต์:** เกมเงียบไปหลายปีเพราะกองเหตุการณ์หมด หรือคนธรรมดาวัยผู้ใหญ่เหลือแต่ข่าว

**วิธีทำ**
- กติกาซ้ำ: ค่าเริ่มต้น `REPEAT_CAP` เป็น 1 เหตุการณ์ที่ควรวนได้ (เช่น ไข้หวัด เงินเดือนออก) ใส่ `cap: n` เอง
- เติมเหตุการณ์ใหม่ภาษาไทย ราว 40–60 เรื่องสำหรับวัย 18–60 และ 60+ ตามโทนเดิม (โลกหลังวันฟ้าแตก ชีวิตประจำวันที่มีเกตอยู่ข้างๆ) แบ่งเป็นเรื่องที่มีขั้นต่อ (ตั้งค่า counter แล้วอีกเรื่องหนึ่งต้องการ counter นั้น) อย่างน้อย 10 คู่ เพื่อเริ่มสร้างความต่อเนื่องก่อนส่วนที่ 2
- หากยังว่างเกินเป้า ลดโอกาสเหตุการณ์สุ่มของผู้ใหญ่ลง และให้หน้าบันทึกสรุปปีที่เงียบเป็นบรรทัดเดียวแทน (ไม่ต้องเปิดตัวเลือก)
- คนรัก: `adultLove` ต้องการ `dating` ซึ่งได้จากเหตุการณ์พบคน (ของเดิม `teenCrush` ตั้ง `firstLove` และเหตุการณ์พบคนใหม่วัยผู้ใหญ่)
- `breakCheck`: ฮันเตอร์ที่อายุเกิน 60 หรือเลิกล่าแล้วได้เหตุการณ์ของคนธรรมดาแทน
- แผนเด็ก: อายุ 0–3 มีแผนของทารก ("เล่นกับพ่อแม่" "นอนกลางวัน") 4–12 ใช้ชุดเดิม
- ข้อความ: แก้ template ใน `src/data/calendar.js`, `src/core/pulse.js` และเพิ่ม `short` ให้หอใน `src/data/towers.js`
- ชื่อไอเทมยังเป็นภาษาอังกฤษตามแนวของคลาสและสกิล (ข้อ 5.3 ของ spec หลัก) **[ผู้ออกแบบ]**
- UI เล็กน้อยที่เห็นจากภาพหน้าจอ: กล่องสรุปลอยบังข้อความบนสุด และปุ่มเสียงทับบันทึก ย้ายให้ไม่ทับ

**ภาพ:** ส่วนนี้ไม่ต้องการภาพใหม่ จึงไม่เพิ่มแถวใน `art/requests.json`

**ตรวจรับ:** `npm test`, `node tools/sim.mjs 1000 --policy normal`, `node tools/playtest.mjs 200`, `node tools/lifecheck.mjs 200`, `node tools/artcheck.mjs` ผ่านทั้งหมด และภาพหน้าจอมือถือ 420px ไม่มีอะไรทับกัน
