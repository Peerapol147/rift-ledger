# Hunter interface — approved visual direction

The owner approved the generated desktop/mobile Hunter UI concept and explicitly requested its implementation in the real game on 14 November 2026. Implement in this session; no additional design approval is pending.

Original ink/navy panels, ice-blue active controls, violet gate accents, angular borders, strong Thai typography. Keep all real game data, life stages, secrets, sprite animations, combat effects and saves. Adapt the concept's illustrative numbers and names to live state; do not copy its invented stats or rewards. No third-party characters/assets.

Desktop: persistent brand/world-date/state header; character sidebar; live scene and decision panel; playback controls; a separate life-plan strip near the decision; journal and navigation. Mobile: compact character summary, short live scene, waiting status, decisions, immediately accessible life-plan controls, then journal. Five navigation positions with an accessible More disclosure for extra visible tabs, without losing any game tab or age restrictions.

Show a clear waiting/running/paused state. Choice cards have visible numbering, real known effects and existing risk/locks. Active narrative title is shown using its discovered definition, never unseen routes. No compulsory highlighted first choice. Plan summary and change disclosure retain selected state through UI redraw and do not pause or mutate the game merely by opening.

Keep existing keyboard, touch cancellation, modal focus trap, storage and import behavior. Respect reduced motion, safe areas, 44px mobile targets, 320px width and large font settings. Render all names/text escaped. Start/end/settings and inventory use the same visual language.

Add an original rainy hunter-city backdrop for city scenes/title presentation; preserve other locations, infants indoors, weather and battle readability. Art stays local and is embedded into play.html via the build so the download remains playable offline.

No changes to mechanics, balance, save schema, narrative content or audio behavior. Existing open export bugs are outside this visual task. Verify unit suite, build/package/art checks, browser responsive layout and actual choices/plans/navigation/settings/save flows. No merge to main or public deployment.
