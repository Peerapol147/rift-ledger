# Compare: Rift Ledger × Way of Xian

วันที่ 13 พฤศจิกายน 2026 · งานวิจัยและแผนสำหรับ Claude · ไม่ใช่การนำเกมอื่นมาสร้างใหม่

## ข้อสรุปที่ใช้ตัดสินใจ

Rift Ledger มีระบบชีวิต อาชีพ การลงเกต ทีม เรื่องต่อเนื่องและมรดกอยู่แล้ว ช่องว่างที่ควรแก้ก่อนคือความน่าเชื่อถือของการกด/เซฟ การเข้าถึงการเตรียมตัว และความต่อเนื่องที่ผู้เล่นรับรู้ได้ **เนื้อเรื่องเป็นแกนหลักเท่ากับ gameplay**: จำนวนเหตุการณ์มากขึ้นไม่ช่วย หากเรื่องถัดไปไม่จำว่าผู้เล่นเลือกอะไร

จุดยืนของเรา: ชีวิตหลังวันฟ้าแตกที่คนธรรมดาและฮันเตอร์ต่างสร้างร่องรอย โลกเดินต่อแม้ตัวละครตาย ส่งต่อทั้งทรัพย์สิน หนี้ทางใจ ผู้คน และสถาบัน รุ่นถัดไปไม่ใช่ตัวละครเดิมที่เปลี่ยนชื่อ เราจะไม่เปลี่ยนเป็นเรื่องผู้ฝึกตนหรือคัดลอกสูตร/พล็อต/บทพูด/หน้าจอของ Way of Xian

## เนื้อเรื่อง: ข้อค้นพบที่ต้องแก้ก่อนเพิ่มจำนวน

### N-01 เงินคืนที่ไม่มีหนี้ (source-confirmed path)

`src/data/team-stories.js` template แรก: ตอนแรกปฏิเสธให้ยืมได้ แต่ตอนที่สามยังเสนอคืน 3,000 โดยไม่ตรวจว่าตอนแรกให้ยืมหรือไม่; `teamStoryMonth` เดิน template ตามลำดับ ส่วน outcomes ไม่มีการบันทึกหนี้รายสมาชิกในเส้นนี้ นี่เป็นข้อขัดแย้งทั้งเรื่องและเศรษฐกิจ ต้องทำ regression ด้วยสองสมาชิกเพื่อไม่ให้ flag ของคนหนึ่งไปปลดอีกคน

### N-02 บทพูดลาไปดูแลครอบครัว แต่สถานะอาจยังอยู่ในทีม

template น้องป่วยมีผลลัพธ์ “ทีมขาดคนไปหนึ่งเดือน” แต่ outcome ที่อ่านมีเพียง loyalty (`ally:10`); `present` ตรวจ alive/hurtUntilM ไม่มี leave field เส้นนี้ต้อง reproduce ระหว่าง operation แล้วแก้ให้ข้อความกับ availability ตรงกัน **ไม่ควรใช้แผลปลอมแทนการลา**

### N-03 ความจำในข้อความไม่เป็น contract

core log เก็บมากสุด 600 แถวและไม่มี stable event identity ในทุกแถว; chapter counters เพิ่มตอนเปิด ไม่ใช่หลักฐานว่าเลือกจบแล้ว จึงห้ามสร้าง journal “บทที่ผ่าน” ด้วยการนับ counter หรือ parse ข้อความไทย แผนจะเพิ่มข้อมูล resolution ที่เป็นโครงสร้าง และไม่แตะ counter เก่ารวดเดียว

### N-04 เสี่ยงทำแผนให้เนื้อเรื่องอยู่ท้ายสุด

แผนนี้เริ่ม narrative audit/เขียนบทไปพร้อมงาน trust และกำหนด **story vertical slice เป็น release gate ก่อนขยาย balance/NPC systems** เรื่องจบต้องมีความหมาย แม้ตัวละครไม่รวย ไม่ได้แรงก์สูง และไม่ตื่นพลัง

N-01/N-02 เป็นการตรวจเส้นโค้ดรอบนี้ ยังไม่ใช่ browser regression ที่รันผ่านแล้ว; N-03 เป็นข้อจำกัดโมเดล; N-04 เป็นความเสี่ยงของแผน ไม่ใช่บั๊กในเกม

## สิ่งที่จะเรียนรู้ และสิ่งที่ไม่ยกมา

เรียนรู้หลักการ: ให้ตัดสินใจโดยรู้ต้นทุน, หยุดเวลาเมื่อกำลังอ่าน, ให้เรื่องจำผล, ให้โลกมีชีวิต, เซฟบอกผลจริง

ไม่นำมา: source/assets/content, ชื่อ/บทสนทนา/จังหวะพล็อตจำเพาะ, เลย์เอาต์แบบตามรอย, สูตร1.7/budget15/สีเป็น permission guard, ลำดับ cultivation, rare-root/tribulation/faction names หรือ balance constants รายงานสูตรเพื่อเข้าใจ ไม่ใช่สเปกสำหรับ implementation

วิธีทำงานของ Claude: อ่าน requirement ของเรา → ออกแบบด้วย code/schema ของเรา → เขียนข้อความใหม่ → ตรวจเกมและทดสอบ → บันทึกเหตุผล ห้ามเปิด HAR เพื่อหยิบ code มาใส่โปรเจกต์ ไม่มี HAR หรือซอร์สคู่เทียบใน PR

## ลำดับการปรับปรุง

1. A: ความน่าเชื่อถือของการกด/เซฟ + narrative audit เริ่มพร้อมกัน
2. B: ข้อมูลก่อนตัดสินใจและ mobile hierarchy; ไม่เปลี่ยนสูตร
3. C: ความต่อเนื่องของเรื่อง + 2 pilot arcs ที่เขียนใหม่ (คนธรรมดา/ฮันเตอร์) + บทส่งต่อรุ่น
4. D: ตรวจสมดุลและคุณภาพบนหลาย seed, playtest ผู้เล่น, ขยายเฉพาะสิ่งที่พิสูจน์ว่าดีขึ้น

## สรุปสำหรับเจ้าของ: เนื้อเรื่องจะดีขึ้นอย่างไร

- **ก่อน:** ผ่านบทขอยืมเงินแล้วตอนต่อไปอาจเล่าเหมือนทุกคนเลือกให้ยืม → **เป้าหมาย:** คนที่ช่วย คนที่ปฏิเสธ และคนที่ยกหนี้ให้ ได้คำตอบและผลตามมาคนละแบบ
- **ก่อน:** ต้องจำเองว่าเรื่องของลูกทีมค้างตรงไหน → **เป้าหมาย:** เปิดเรื่องที่ผ่านมาแล้วเห็นสิ่งที่เคยเกิดจริง โดยไม่เฉลยตอนหน้า
- **ก่อน:** ความสำเร็จในหน้าจออาจเด่นที่แรงก์/เงิน → **เป้าหมาย:** ชีวิตคนธรรมดาที่ช่วยคนหนึ่งหรือทำให้สถาบันเปลี่ยน มีบทสรุปที่มีน้ำหนักเช่นกัน
- **ก่อน:** มรดกมีฐานเชิงระบบแล้ว → **เป้าหมาย:** รุ่นลูกได้พบร่องรอยสาธารณะของสิ่งที่คนรุ่นก่อนทำ โดยไม่รับความรู้ลับหรือบัฟฟรี

ชื่อเรื่องทดลองและรายละเอียดใน design เป็นข้อเสนอที่เขียนขึ้นสำหรับเรา Claude ต้องเทียบกับบทเดิมก่อนลงมือ เพื่อให้เป็นส่วนหนึ่งของโลกเดียวกันและไม่สร้างเรื่องซ้ำกันเอง
